# 生络 ShengLuo

以人为单位的个人智能伙伴。它依托 DeepSeek Harness 的模型、Agent、工具、审批与文件能力，
持续理解一个人的真实处境，并真正替他把事情推进到可以核对的成果。

生络不是另一个客户端，也不是 DSH 的换皮：它是 **DSH 原生插件**，侧栏只有一个「生络」入口，
点进去是一块网络主面板；会话、工具调用、审批、文件预览、Agent preset、Skills、MCP、
插件管理全部继续使用 DSH 自己的界面和能力。

## 它做什么

- **一个智能核心 + 少量真实节点。** 中间是生络核心，周围默认只放 5–9 个与当前这件事有关的真实节点：
  你的现实、项目、目标、执行、成果、待你决定、知识。节点全部带来源，关系用普通话说清楚。
  技术名称（Skill、工具、MCP、API）不进网络。
- **一句话推进一件事。** 底部只有一个输入框：「今天你想推进什么？」。
  点「下一步」先给你三行契约——我会用到 / 我会交付 / 需要你定——你点头才动手。
- **真执行，不是演示。** 每件事跑在一个真实的 DSH 原生会话里：真实工具调用、真实审批、
  真实写进工作区的文件。插件不自己造任务系统，也不接管执行。
- **审批回原生界面。** 需要你允许或拒绝时，面板把你送到那个原生会话，你点允许或拒绝；
  拒绝就停，如实显示停下，不会假装完成。
- **成果回到项目。** 产出就是工作区里的文件，可以打开核对；不会复制成第二份「个人记忆」。
- **理解个人现实要授权。** 家庭空间（ymai.love）走设备授权，只读、只限你本人有权访问的部分，
  启动时不全量同步，撤回后立刻停止读取。未授权时个人现实显示「未知」，不用测试数据或猜测填空。
  线上接口：`https://ymai.love/api/integrations/shengluo`；授权页：`https://ymai.love/connect/shengluo`；
  撤回入口也在家庭空间：我的 → 隐私和数据 → 生络连接授权。

## 怎么用

1. 打开 DeepSeek Harness，点左侧「生络」。
2. 在底部写一句你想推进的事，点「下一步」，看一眼那三行契约，点「开始工作」。
3. 需要你决定时，点「前往会话」在 DSH 原生界面里允许或拒绝。
4. 做完点「打开成果」，或用左侧「成果」看这次写下的文件。
5. 想要它理解你的生活，在右侧「个人现实：尚未授权」那里点「连接家庭空间」，
   在浏览器里用你自己的账号确认这一次授权。
6. 授权之后，点「查一下这件事的现实」——它才会按这件事去问一次（不会在启动时全量同步），
   查到的条目会变成网络上的「现实」节点，带事实状态、来源、时间；点节点可以看原始对话证据（逐字）。

左侧导航：今天 / 项目 / 成果 / 知识 / 插件。
- 今天：网络与当前这件事。
- 项目：本机 DSH 里真实存在的项目目录。
- 成果：这次以及最近写在工作区里的文件。
- 知识：MKI 知识目录里的条目（没配置就是空的，不会编）。
- 插件：直接打开 DSH 原生插件管理，不在插件里再造一套。

## 边界（重要）

- **只读个人现实。** 生络不会写入、修改或遗忘家庭空间里的任何数据。
- **不越权。** 只请求 `conversation.read.own` 与 `personal_reality.read.own` 两个 scope；
  其他家庭成员的私人对话读不到（服务端与本插件两侧都不提供）。
- **不碰登录态。** 家庭空间的登录 Cookie 永远不交给 DSH；插件只持有这一次集成授权的 bearer token，
  存在 DSH 自己的凭据库里（`$DSH_HOME/.credentials.yaml`，0600），不进插件数据文件、不进日志。
- **不复制正文。** 个人现实与对话正文只在本次响应和内存里，不写入本地产品状态文件。
- **不替你做决定。** 授权、撤销、打开本地文件这类授予权限的动作只留给你，不注册成 Agent 工具。

## 支持的 DSH 版本

- 目标版本：**DeepSeek Harness 0.2.2-rc.5**（`package.json` 的 `engines.dsh` 声明
  `>=0.2.2-rc.5 <0.3.0-0`）。
- 依赖的是 DSH 公开的插件契约：`main` / `sidebar.panellist` 槽位、`sessions` / `uiWorkspace` /
  `layout` 客户端服务、`ctx.tools.register`、`ctx.agents`、`ctx.agentPresets`、`ctx.credentials`、
  `ctx.webServer` + `ctx.connection` 连接信任。
- 上游升级后可能需要维护：DSH 尚未承诺这些接口永久稳定。每次升级请跑一次最小兼容测试
  （安装 → 侧栏出现「生络」→ 面板渲染 → 发起一件事并真实执行）。仓库里
  `tests/acceptance.mjs` 会覆盖这条链路。

## 已知限制

- Family Space 的服务端接口由 Family Space 仓库实现；在该服务端上线前，连接与读取只会
  如实报错，不会伪造「已连接」。插件侧契约测试见 `tests/family-space-contract.mjs`。
- 知识来源需要配置 MKI 目录（`knowledgeDir`）；没配置时知识是空的，不生成假条目。
- 网络是**产品层的可重建投影**：删掉插件数据不会丢任何事实，因为权威分别在
  Family Space、项目仓库、DSH 会话日志和你的工作区文件里。
